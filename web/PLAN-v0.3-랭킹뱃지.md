# v0.3 계획 — 전투력 랭킹 뱃지·점수별 서버 랭킹

요청(承雲, 2026-10-05): 서버 전투력 랭킹 10000·1000·100·10위 이내를 각각 보라·핑크·주황·골드 뱃지로 캐릭터 카드의 "전투력" 글자 옆에 달고,
개요·스탯 탭에는 종합/전투력/생활력/매력 서버 랭킹을 보인다. 순위는 넥슨 랭킹 페이지에서 가져온다. 캐릭터 이름은 사용자가 입력한 이름(별칭)을 쓴다.

## 1. 조사 결과 (2026-10-05, 읽기 전용 확인)

- 페이지: `https://mabinogimobile.nexon.com/Ranking/List?t=N` (로그인 없이 열린다). 종류: `t=1` 전투력, `t=2` 매력, `t=3` 생활력, `t=4` 종합.
- 검색: `POST /Ranking/List/rankdata` (multipart 폼) 필드 `t`(종류) · `pageno`(1) · `s`(서버) · `c`(클래스, 전체는 `0`) · `search`(캐릭터명).
  서버 번호: 1 데이안, 2 아이라, 3 던컨, 4 알리사, 5 메이븐, 6 라사, 7 칼릭스, 8 몰리.
- 응답은 HTML 조각이다. 검색한 캐릭터가 들어 있는 쪽(20명)을 돌려주고, 그 캐릭터의 항목에 `class="item … on"`이 붙는다.
  항목: `<dt>N위</dt>`(순위), `data-charactername`(이름), 클래스 이름, 점수(`type_1` 전투력, `type_2` 매력, `type_3` 생활력). 종합은 점수가 4개(합계, 전투력, 생활력, 매력 순)다.
  실측: 종합 245,172 = 전투력 141,099 + 생활력 45,237 + 매력 58,836 (합산이 맞다).
- 이름은 **완전 일치만** 검색된다(부분 일치·다른 서버는 결과 없음 → 응답에 "결과가 없습니다."가 있고 102바이트).
- 이름을 알려 주는 게임 CLI 항목이 없어(`get_my_info`에 이름 없음) 이름은 별칭(`CustomName`)을 쓴다.

## 1-1. 막힌 점: 서버가 직접 가져올 수 없다 (2026-10-05)

- 프로그램(앱 서버·curl)이 같은 주소를 호출하면 **403 + Cloudflare 보안 검사**("접속을 위해 보안 검사를 진행해 주세요")가 돌아온다. 브라우저에서는 사람이 검사를 통과해 열린다.
- 이 검사는 자동 접속을 막는 장치이므로 **우회하지 않는다**(검사 통과 흉내·쿠키 가로채기 등 불가). 넥슨 공개 API(Open API)에는 마비노기 모바일 랭킹이 없다(마비노기 영웅전 등만 지원). 게임 CLI(28종)에도 랭킹이 없다.
- 따라서 **데이터 수집 경로를 바꾼다**: 앱 서버는 순위 값을 *받아서 저장·표시*만 하고, 값은 (A) 사용자가 자기 브라우저에서 랭킹 페이지를 열고 누르는 북마크릿, (B) 화면의 수동 입력으로 넣는다.
  - (A) 북마크릿: 사용자가 ranking 페이지에서 직접 누른다. 사용자의 브라우저가 로컬 앱에서 대상(별칭·서버) 목록을 받아 와 같은 페이지의 검색을 1.2초 간격으로 돌리고 결과를 로컬 앱으로 보낸다.
  - (B) 수동 입력: 개요·스탯 탭에서 종류별 순위를 직접 적는다.

## 2. 규칙

- 뱃지(전투력 서버 순위): 10위 이내 골드, 100위 이내 주황, 1000위 이내 핑크, 10000위 이내 보라, 그 밖은 없음.
- 순위는 "서버 전체 클래스" 기준(`c=0`).
- 별칭이 없으면 조회하지 않는다. 안내만 보인다("캐릭터명을 입력하면 랭킹을 볼 수 있어요").
- 서버는 캐릭터의 `RealmName`으로 정한다. 표에 없는 서버면 조회하지 않는다.
- 같은 이름의 다른 캐릭터(동명이인) 방지: 응답의 클래스가 저장된 직업과 다르면서 전투력 차이가 20%를 넘으면 일치하지 않는 것으로 본다.
- 순위가 없으면(결과 없음) "순위 정보 없음"으로 보이고 뱃지는 없다.

## 3. 구조

Core(순수 로직, 테스트 쉬움) · Web(입출력).

| 위치 | 내용 |
|---|---|
| `Core/Ranking/RankModels.cs` | `RankKind`(종합·전투력·생활력·매력과 사이트 `t` 값), `RankEntry`, `RankTier`, `RankTiers.Of(rank)`, 서버 번호 표 |
| `Core/Ranking/RankingParser.cs` | 응답 HTML → `on` 항목의 순위·점수·클래스. "결과 없음"·형식 변경은 구분해 돌려준다 |
| `Web/Services/RankingIngest.cs` | (1-1 반영) 순위 입력을 받는 곳: 북마크릿·수동 입력 둘 다 같은 형식. 값 검증(순위 1 이상, 서버·종류 범위, 알려진 캐릭터 키), 출처·시각 기록 |
| `Web/Services/RankingStore.cs` | `rankings.json`: 캐릭터 키 → { 조회한 이름, 서버, 조회 시각, 종류별 순위·점수, 상태 } |
| `Web/Services/RankingService.cs` | 저장·조회. 값마다 "받은 시각"을 보이고, 6시간이 지나면 "오래됨" 표시(자동 삭제 안 함). 별칭이 바뀌면 그 캐릭터의 값은 "별칭이 바뀌어 다시 가져와야 함"으로 표시. 잠금(lock)으로 동시 입력을 막는다 |
| (삭제) `RankingWorker` | 서버가 직접 가져오지 않으므로 백그라운드 조회가 없다 |
| 설정 | `RankingEnabled`(기본 켬). 설정 화면에 켜고 끄기와 "별칭과 서버 이름이 넥슨 랭킹 페이지로 전송됩니다" 안내 |
| API | `GET /api/rankings`(전체), `GET /api/rankings/targets`(북마크릿이 가져갈 별칭·서버 목록), `POST /api/rankings/import`(북마크릿·수동 입력), 북마크릿용 CORS는 넥슨 랭킹 주소 한 곳만 허용. 카드·헤더 응답에는 전투력 순위·등급만 얹는다 |
| 화면 | `RankBadge`(◆ 모양, 보라·핑크·주황·골드, `aria-label`·툴팁에 "서버 N위"). 전체 탭 카드의 "전투력" 옆·상단 전투력 칩 옆에 뱃지만. 개요·스탯 탭에 4종 랭킹 목록(순위·점수·조회 시각·갱신 버튼, 종합은 "전투력+생활력+매력") |

## 4. 테스트

- 파서: 실측 응답 조각을 고정 데이터로 저장(성공 4종, 결과 없음, 마지막 쪽, 특수문자 이름, 형식이 깨진 경우).
- 등급 경계: 10/11, 100/101, 1000/1001, 10000/10001.
- 서비스(가짜 HTTP 처리기): 유효기간, 별칭 변경, 쿨다운, 실패 시 이전 값 유지, 백오프, 요청 간격, 설정 끔, 동명이인 걸러내기.
- API·화면: 가짜 랭킹 응답으로 카드·헤더·개요·스탯, 접근성(axe) 두 테마, 폭별 잘림 없음.
- 실제 사이트 호출은 자동 테스트에 넣지 않는다(수동 한 번 확인).

## 5. 위험과 대응

- 사이트 형식이 바뀌면 파서가 실패한다 → 실패를 구분해 로그에 남기고 화면에는 "조회 실패", 이전 값은 유지.
- 사이트에 부담을 주지 않는다 → 호출은 캐릭터당 6시간에 4건, 1.2초 간격, 직렬, 백오프, 끌 수 있음.
- 외부 전송 → 별칭·서버 이름만 보낸다. 설정 화면과 README에 밝힌다.
- 별칭이 실제 캐릭터 이름과 다르면 순위가 없거나 남의 순위가 나올 수 있다 → 동명이인 걸러내기, 순위 정보 없음 안내.

## 7. 리뷰 반영 (2026-10-05, 서브에이전트)

- 별칭 변경 감지: 값에 "조회한 이름"을 같이 저장하고, 표시할 때 현재 별칭과 다르면 "별칭이 바뀌었다"로 처리한다(별도 신호 불필요).
- 같은 서버·직업 캐릭터가 여럿(`#2`)이어도 키가 다르므로 각자 별칭으로 조회한다. 별칭이 같은 캐릭터가 둘이면 두 번째는 건너뛰고 안내한다.
- 서버 이름이 비었거나 표에 없으면 조회 대상에서 뺀다. "캐릭터 선택 중" 화면의 흐린 캐릭터는 대상에 넣지 않는다.
- 저장소는 `lock`과 임시 파일 교체로 동시 입력을 막는다(기존 `JsonFileStore` 사용).
- 값마다 마지막 성공 시각을 항상 같이 보인다.
- 테스트에 유효기간 경계(5시간 59분/6시간 1분)와 별칭 변경 뒤 오래됨 표시를 추가한다.
