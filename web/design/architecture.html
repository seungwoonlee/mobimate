3. 데이터가 움직이는 길 — 네 가지 장면

① 화면을 열면 — “읽기”

  1. 브라우저가 GET /api/…로 캐릭터·숙제·가방을 요청
  2. 서버의 GameViews가 QueryCache를 먼저 확인(몇 초 이내면 재사용)
  3. 없으면 GameCli가 get_my_info 등을 실행
  4. 게임이 JSON을 돌려줌 → 오류·연결끊김 응답은 여기서 걸러짐
  5. 서버가 화면용으로 가공해서 응답 → 브라우저가 그림

② “수거해줘” 같은 명령을 내리면 — “쓰기”

  1. 브라우저 AI 도우미에 말하면 서버가 CommandIntentParser로 “수거” 의도를 판정
  2. 화면이 가공물 목록에서 시설마다 하나씩 골라 POST /api/actions/collect (LAN의 다른 컴이어도 서버는 게임 PC에서 실행)
  3. GameActions가 complete_altering_work를 CLI로 실행
  4. 게임이 “수락/거절/중단”을 답함 → CliEnvelope.ActionError가 거절(blocked·timeout·가방 가득 …)을 읽어 실패로 알림 (11-12 수정 전에는 이걸 보지 않고 “성공”이라 했음)
  5. 성공하면 숙제 판정에 “앱이 수거함”을 알리고, 캐시를 비워 화면을 새로 읽음
채집·행동 정지도 같은 길을 씁니다. 채팅은 별도 레인(write_chat)이라 오래 걸리는 채집이 막지 않습니다.

③ 숙제가 저절로 체크되는 길 — “자동 판정”

  1. AutoWatcher가 1초마다, CharacterWatcher가 캐릭터 전환을 살핌
  2. 퀘스트·미션·재화·현재 지역을 HomeworkObservation 한 묶음으로 만듦
  3. HomeworkEvaluator가 카탈로그 규칙(퀘스트 사라짐, 지역 안 보상, 증표 증가 …)으로 판정
  4. homework_records.json에 저장 (바뀐 항목만)
  5. SseHub가 homework.changed를 방송 → 열려 있는 모든 화면이 다시 읽음

④ 마이크로 말하면 — “음성 → 채팅”

  1. 게임 PC에서 단축키(왼쪽 Ctrl+Space) → SttService.Start · 신호음 → 마이크 열기
  2. 소리를 100ms씩 선택한 엔진에 넘김: Zipformer는 말하는 도중 글자를 보여 주고, Qwen3는 말이 끝나길 기다렸다 한 번에 인식
  3. 문장 확정 → 학습된 교정 → (켜져 있으면) Ollama로 AI 다듬기
  4. 자동 전송이 켜져 있으면 ChatService→write_chat으로 게임에, 아니면 입력창 초안으로
  5. 결과·진행은 stt.partial/final 이벤트로 이 PC 화면에만 방송
음성은 보안상 게임 PC 본체에서만 켜고 설정할 수 있습니다. LAN 폰·노트북에서는 안 되는 것이 정상입니다.
